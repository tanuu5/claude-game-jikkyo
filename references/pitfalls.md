# つまずいた点と対処

## 撮影

- **`rsync --exclude dist` が node_modules の中の dist まで消した**（vite が起動しない）。除外は `/dist` のように根元に限るか、node_modules を別にコピーする。
- **フォルダ名の濁点**：macOS のパスは NFD（「ゲ」が「ケ＋゛」）。Node の URL 表示では化けて見えるが動作に問題はない。ファイル名を文字列で比較するときだけ注意。
- **静的サーバーで writeHead の後に readFileSync が失敗**すると落ちる（favicon の 404 など）。読んでからヘッダを書く（修正済み）。
- **ポインタロックはヘッドレスで使えない。** ロックが外れると一時停止するゲームが多い。アダプタの `pre` でロック済みのふりをするか、ゲームの「ロック失敗」フラグを立てる。
- **CSS アニメーションは実時間で進む。** play-server が毎コマ `document.getAnimations()` を止めて仮想時計ぶん進めている。
- **読み込み中に setTimeout を待つゲーム**がある。時計を止めるのは `ready` が真になってから。
- **構え（右ボタン）の押しっぱなし**：AQUA BLUE で `keepAim` のあと解除を忘れ、次の移動がのろくなった。押しっぱなしにする操作は `endStep` で必ず戻す。
- **`lookAt` は三人称カメラの画面で計算する。** 一人称に切り替わる操作（カメラを構える）と同時だと少しずれる。構えてから、もう一度 `lookAt` で合わせる。
- **地形が分からないときは地図とスキャンを使う。** LAST COURIER では浅瀬がわからず下流へ迷走した（結果的に良い見せ場になった）。迷いは memo に残す。

## 音

- `vaudio.js` は `OfflineAudioContext` を最初に `audioSeconds` ぶん確保する（既定 900 秒、約 350MB）。長く遊ぶならアダプタで増やす。
- `<audio>` 要素や音声ファイルを `HTMLMediaElement` で鳴らすゲームは録れない（その場合は Web Audio に載せ替えるパッチをコピー側に当てる）。
- ゲームの素の音量が小さいことがある（LAST COURIER は平均 -32 dB）。`volumedetect` で見て `game_audio.gain` を上げる。
- 書き出しで loudnorm（-16 LUFS）をかけるので、全体の音量はそろう。声とゲーム音の比は gain / duck で決める。

## 編集

- 1080p60 で雨や粒子の多い映像は重い。CRF 18 で 2.5 分 978MB になった → CRF 20＋maxrate 20M で 300MB。
- カットの途中で読むのをやめた ffmpeg が Broken pipe を出すが正常（表示は消してある）。
- 同じコマ範囲を 2 回使うカット（予告・リプレイ）では、セリフと演出に `cut` を付けないと最初の出番に付いてしまう。
- 作品自身のタイトル画面にタイトルのテロップを重ねると二重になる。
- バランス計や会話ウィンドウが画面下にある作品では、字幕の高さ（`caption_y`）を上げる。
- 早送りのバッジは既定で上中央（左上は多くの作品で HUD がある）。重なるなら `badge` で動かす。

## 時間の目安（Apple Silicon の Mac）

- 調査（サブエージェント）：約 3〜4 分
- プレイ：素材 4 分で約 20 分（1 手ごとに画面を見て判断）
- 台本：15〜20 分
- 書き出し：プレビュー約 1 分、本番約 3〜4 分（2.5 分の動画）
